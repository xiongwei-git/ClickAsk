# ClickAsk Bookmarklet MVP 开发任务书

## 1. 项目定位

ClickAsk 第一版是一个基于 bookmarklet 的页面上下文采集与 prompt 生成工具。

用户点击书签后，ClickAsk 会在目标网页中注入一个轻量元素选择器。用户可以点选或框选页面区域，再输入一句大白话需求，工具自动提取页面上下文并生成结构化 prompt，供用户复制到 Codex、Claude、Gemini、ChatGPT、Kimi 等 AI 工具中使用。

第一版重点验证核心闭环：

```text
点击书签 -> 选择页面内容 -> 输入自然语言问题 -> 生成专业 prompt -> 复制给 AI
```

## 2. 核心痛点

用户在和 AI 沟通时，经常遇到三个问题：

- 不知道如何准确描述页面上的“那个东西”。
- 会写很多大白话、语气词和重复描述，浪费 token。
- 不知道该给 AI 补充哪些上下文，导致回答不准。

ClickAsk 的第一版先解决前两个问题的一部分：

- 用点选/框选解决“那个东西”的定位问题。
- 用模板化 prompt 解决大白话变成结构化提问的问题。

模型增强、语音输入、prompt 评分、模板市场等能力暂不进入 MVP。

## 3. 目标用户

第一版面向普通 AI 用户和轻度开发者，而不是企业团队或专业 prompt 工程师。

典型用户：

- 看到网页上的一段内容，想问 AI 解释、总结、分析。
- 看到数据看板或表格，想问 AI 分析异常或趋势。
- 看到报错页面，想问 AI 帮忙判断原因。
- 看到一个 UI 区域，想让 AI 给出改进建议。

## 4. 使用场景

### 4.1 网页内容提问

用户选中网页上的一段内容，输入：

```text
帮我总结一下这块内容
```

工具生成包含页面标题、URL、选中区域文本和总结要求的 prompt。

### 4.2 数据看板分析

用户框选表格或指标卡，输入：

```text
这个数字为什么下降这么多
```

工具生成包含表格可见文本、页面上下文和分析任务的 prompt。

### 4.3 报错页面排查

用户选中错误提示区域，输入：

```text
这个错误怎么解决
```

工具生成包含错误文本、页面 URL、DOM 上下文和排查要求的 prompt。

### 4.4 UI 改进建议

用户选中页面局部，输入：

```text
这里怎么优化一下
```

工具生成包含元素结构、可见文本、HTML 片段和 UI 改进要求的 prompt。

## 5. 产品原则

- 轻：不安装浏览器插件，不登录，不依赖后端。
- 快：点击书签即可启动，用完复制即可离开。
- 准：优先提取用户选中区域的上下文，而不是全页噪声。
- 可编辑：生成前后都允许用户保留自己的原话。
- 不绑定 AI：只生成 prompt，不自动发送给任何 AI 服务。
- 本地优先：第一版不上传页面内容，不调用模型 API。

## 6. 第一版范围

### 6.1 必做功能

#### 安装页

- 提供一个可拖到书签栏的 bookmarklet 链接。
- 页面加载时读取本地 `assets/clickask.css` 和 `assets/clickask.js`。
- 将 CSS 注入逻辑和 JS 主逻辑打包进 `javascript:` URL。
- 如果资源加载失败，展示错误提示。

#### 注入启动

- 用户点击书签后，在目标页面注入 ClickAsk。
- 如果已经注入，不重复创建 UI。
- 注入后给页面元素分配内部 id，例如 `data-clickask-id`。
- 注入一个悬浮小窗和 hover/selection overlay。

#### 元素选择

- 鼠标移动时显示 hover 框。
- 单击选择一个元素。
- Shift + 单击进行多选。
- 鼠标拖拽框选多个元素。
- Escape 清空选择。
- 支持关闭工具并清理注入 UI。

#### 基础导航

实现单元素选中时的键盘导航：

- ArrowUp：选中父元素。
- ArrowDown：选中第一个有意义子元素。
- ArrowLeft：选中上一个有意义兄弟元素。
- ArrowRight：选中下一个有意义兄弟元素。

#### 悬浮小窗

第一版采用右下角悬浮小窗，不做侧边栏和底部抽屉。

小窗包含：

- 状态：Ready / Paused。
- 已选元素列表。
- 大白话输入框。
- prompt 类型选择。
- Copy Prompt 按钮。
- Close 按钮。

#### 大白话输入

- 用户可以输入自然语言需求。
- 输入内容保留在本次注入会话中。
- 生成 prompt 时把用户原话放入 `用户原始需求`。
- 同时根据任务类型生成更专业的 `请完成` 部分。

#### Prompt 类型

第一版提供固定类型，不接模型：

- 自动判断
- 通用提问
- 总结内容
- 分析原因
- 排查问题
- UI/体验改进
- 代码修改建议

`自动判断` 使用本地轻量意图识别：基于用户输入和选中内容的关键词、错误信息、表格/数字特征、交互元素特征和 React/source 线索推荐 prompt 类型。用户可以手动切换到固定类型，手动选择优先于自动推荐。

#### 多语言

- UI 文案跟随浏览器语言。
- 第一版支持中文和英文。
- `navigator.language` 或 `navigator.languages[0]` 以 `zh` 开头时使用中文，否则使用英文。
- 生成的 prompt 标题、字段名和任务指令也跟随同一语言。

#### 上下文提取

每个选中元素至少提取：

- 元素标签名。
- 可读标签：id、class 或文本预览。
- CSS selector。
- XPath。
- 可见文本，压缩空白并截断。
- HTML 片段，截断。
- `data-*` 属性，排除工具自身 id。
- 可访问性信息：role、aria-label、title、alt。
- React debug 信息，如果目标页面可读。

页面级上下文至少提取：

- URL。
- `location.pathname`。
- `document.title`。
- 生成时间。
- viewport 宽高。

#### Prompt 生成

输出 Markdown 格式，结构建议如下：

```markdown
# 页面上下文提问

## 页面信息
- URL: ...
- 标题: ...
- 路径: ...
- Viewport: ...

## 用户原始需求
...

## 选中内容

### 1. ...
- selector: ...
- xpath: ...
- role/name: ...
- text: ...
- html: ...

## 请完成
1. 基于选中内容和页面上下文理解用户需求。
2. 如果信息不足，请明确说明缺少什么。
3. 给出结构化、可执行的回答。
```

不同 prompt 类型只调整 `请完成` 部分，不改变上下文采集格式。

#### 复制能力

- 点击按钮复制 prompt 到剪贴板。
- 支持 `Cmd/Ctrl + C` 在有选中元素时复制 prompt。
- `navigator.clipboard.writeText` 失败时使用 `document.execCommand("copy")` 降级。
- 复制成功后按钮显示短暂反馈。

### 6.2 可选功能

如果实现成本低，可以纳入第一版：

- 面板拖拽移动。
- 最小化面板。
- `Space` 暂停/恢复选择。
- `Cmd/Ctrl + Z` 撤销选择。
- 每个选中元素添加独立备注。

这些能力不是第一版验证价值的硬前提。

### 6.3 明确不做

第一版不做：

- 浏览器插件。
- 登录账号。
- 云端同步。
- 模型调用。
- 大白话智能改写。
- 语音输入。
- 截图上传。
- prompt 评分。
- 模板市场。
- 历史追问链。
- 自动发送到 ChatGPT/Claude/Gemini。
- 团队版能力。

这些功能进入后续 Roadmap。

## 7. 交互流程

### 7.1 安装流程

1. 用户打开安装页。
2. 把 `ClickAsk` 链接拖到浏览器书签栏。
3. 打开任意网页。
4. 点击书签启动工具。

### 7.2 使用流程

1. 用户点击书签。
2. 页面出现 hover 框和右下角悬浮小窗。
3. 用户单击或框选页面区域。
4. 小窗显示已选元素。
5. 用户输入大白话需求。
6. 用户选择 prompt 类型。
7. 用户点击 Copy Prompt。
8. 用户粘贴到 AI 工具中。

### 7.3 退出流程

1. 用户点击 Close。
2. 工具移除所有 overlay、面板、弹窗。
3. 工具解绑所有事件监听。
4. 页面恢复正常交互。

说明：第一版可以不移除已写入页面元素的 `data-clickask-id`，但需要在文档中说明。后续可增加清理策略。

## 8. 技术方案

### 8.1 技术形态

第一版采用纯前端 bookmarklet：

```text
index.html
assets/
  clickask.js
  clickask.css
docs/
  development-brief.md
  operator-runbook.md
```

不使用构建工具也可以完成第一版。若后续单文件膨胀，再引入打包。

### 8.2 模块边界

即使第一版写在单个 `clickask.js` 中，也建议按以下模块组织：

```text
boot                 # 初始化、防重复、销毁
domIds               # 元素 id 分配
targetResolver       # hover/click 目标解析
selectionStore       # 选中状态、撤销、备注
overlays             # hover box、selection box、marquee
panel                # 悬浮小窗
contextExtractors    # DOM/page/react/xpath/a11y 信息提取
promptBuilder        # prompt 类型与 Markdown 输出
clipboard            # 剪贴板写入与降级
keyboard             # 快捷键
```

### 8.3 命名空间

使用统一前缀，避免污染页面：

- CSS class: `ca-*`
- DOM attribute: `data-clickask-id`
- root class: `ca-root`

所有工具 UI 都要带 `ca-root`，目标解析时必须跳过工具自身元素。

### 8.4 事件策略

- `mousedown`、`click`、`mousemove`、`mouseup`、`keydown` 绑定在捕获阶段。
- 点击页面内容时阻止原页面 click 行为。
- 点击工具 UI 时不触发选择。
- 滚动和 resize 时重新定位 overlay，并用 `requestAnimationFrame` 节流。

### 8.5 目标解析策略

从 `event.target` 向上寻找有意义元素：

- 跳过工具自身 UI。
- 跳过不可见元素。
- 跳过尺寸过小元素。
- 优先选择有直接文本、媒体、表单、链接、按钮或多个子元素的节点。

### 8.6 上下文截断策略

为避免 prompt 过长，第一版设置硬限制：

- 单元素 text 最多 500 字符。
- 单元素 HTML 最多 600 字符。
- 最多输出 20 个选中元素。
- 总 prompt 建议控制在 8,000 字符以内。

如果超过限制，在 prompt 中标注：

```text
[内容已截断]
```

## 9. Prompt 模板

### 9.1 通用提问

```markdown
## 请完成
1. 理解用户原始需求，并结合选中内容回答。
2. 如果用户描述不清楚，请先说明你的理解，再给出回答。
3. 如果页面上下文不足，请明确指出缺少的信息。
```

### 9.2 总结内容

```markdown
## 请完成
1. 总结选中内容的核心信息。
2. 用简洁条目输出。
3. 保留关键数字、结论和专有名词。
```

### 9.3 分析原因

```markdown
## 请完成
1. 分析选中内容中可能的问题、异常或趋势。
2. 给出可能原因，并按可能性排序。
3. 说明还需要哪些额外信息才能确认结论。
```

### 9.4 排查问题

```markdown
## 请完成
1. 判断选中内容显示的问题是什么。
2. 给出可能原因。
3. 给出可执行的排查步骤。
4. 如果是技术错误，请尽量解释错误含义。
```

### 9.5 UI/体验改进

```markdown
## 请完成
1. 分析选中区域的可读性、层级、布局和交互问题。
2. 给出具体改进建议。
3. 如果适合，请给出修改前后的文案或布局建议。
```

### 9.6 代码修改建议

```markdown
## 请完成
1. 根据选中元素上下文判断它可能对应的前端实现。
2. 优先使用 source、react、selector、data-* 等信息定位代码。
3. 给出清晰的修改建议。
4. 不要只建议修改浏览器 DOM，应说明需要修改源码。
```

## 10. 验收标准

### 10.1 基础运行

- 安装页可以生成可拖拽 bookmarklet。
- 在普通网页、localhost 页面、React dev 页面上可以启动。
- 重复点击书签不会重复注入多个面板。
- Close 后页面可正常点击和滚动。

### 10.2 选择体验

- hover 框能跟随鼠标定位到合理元素。
- 单击能选中元素并显示 selection overlay。
- Shift + 单击可以多选。
- 拖拽框选可以选择多个元素。
- Escape 可以清空选择。
- 工具 UI 自身不会被选中。

### 10.3 Prompt 输出

- 未选择元素时，Copy 按钮不可用或给出提示。
- 有选择和用户输入时，可以复制 Markdown prompt。
- prompt 中包含页面信息、用户原始需求、选中内容和任务指令。
- CSS selector、XPath、text、HTML 至少可输出。
- React 页面在开发模式下尽量输出 source/react 信息；没有时不报错。

### 10.4 稳定性

- 页面滚动后 overlay 位置能更新。
- resize 后 overlay 位置能更新。
- 复制失败时有降级方案。
- 一个页面选择 20 个以内元素时无明显卡顿。

## 12. 已定决策

- 第一版使用 bookmarklet，不做浏览器插件。
- 第一版使用悬浮小窗，不做侧边栏和底部抽屉。
- 第一版不调用模型，用规则模板生成 prompt。
- 第一版只复制 prompt，不自动发送给 AI。
- 第一版聚焦页面上下文提问，不做浏览器插件、模型调用或自动发送。
