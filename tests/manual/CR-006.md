# CR-006 手动测试用例

## 1. 本地降级（无 manifest.json）

1. 终端：`python3 -m http.server 18082`
2. 浏览器打开 `http://127.0.0.1:18082/`
3. **预期**：
   - 「拖到书签栏」链接生成成功（loading 状态消失）
   - DevTools Network 面板：`manifest.json` 状态 404
   - `assets/clickask.css` / `assets/clickask.js` 请求 URL **不带** `?v=`
   - 「load-error」隐藏

## 2. 本地有 manifest.json 时拼 query

1. 在 `assets/manifest.json` 写入：
   ```json
   { "css": "a1b2c3d4", "js": "e5f6g7h8", "builtAt": "2026-05-18T00:00:00Z" }
   ```
2. 强刷安装页
3. **预期**：
   - DevTools Network：`assets/clickask.css?v=a1b2c3d4`、`assets/clickask.js?v=e5f6g7h8`
   - 书签链接生成成功
4. 验证完后删除 manifest.json，避免影响后续 CR

## 3. 部署链路（线上）

1. 改一行 css（例如调整 `.ca-panel` 阴影）
2. 跑 `./scripts/deploy.sh`
3. **预期**：
   - 控制台输出 `manifest.json: css=<8位hash> js=<8位hash>`
   - `http://clickask.tedxiong.com/assets/manifest.json` 可访问，hash 与上一次不同
   - DevTools Network：css 请求带新的 `?v=`，状态 200（不是 304）
   - 已安装的老书签点击后体验是新版（因为 install 页重新拉了带新 hash 的 js）

## 4. 边界

| 场景 | 预期 |
|------|------|
| manifest.json 内容是非 JSON（如 `<html>`） | catch 触发，降级到无 hash 拉取 |
| manifest.json 仅有 `css` 没有 `js` | css 带 query，js 不带，两者都成功 |
| 网络断开 | 「load-error」显示文案，与 CR-006 之前行为一致 |
